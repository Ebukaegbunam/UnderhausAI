## Phase 1 Core — Scraper + Underwriting Engine

**What was built:**

Full backend feature stack across these new files:

| File | Purpose |
|------|---------|
| `models/listing.py` | All Pydantic schemas: `Listing`, `UserProfile`, `UnderwritingResult`, `ListingSearchRequest/Response`, enums |
| `scrapers/zillow.py` | Zillow scraper via RapidAPI (`zillow-com1`). Geocodes input → bounding box → fetches listings → filters by Haversine distance. Full error handling: rate limit, 403, timeout, parse errors. Mock mode for dev. |
| `services/geocoder.py` | Nominatim (OpenStreetMap) geocoder. Accepts zip or address, returns lat/lng. Async, graceful error messages. |
| `services/cache.py` | TTL in-memory cache (1h for listings, 24h for geocode). Module-level singletons. Swap for Redis at scale. |
| `agents/underwriting_engine.py` | Phase 1 underwriting: mortgage calc, rent estimation, all expense line items, CoC return, cap rate, GRM, DSCR, verdict (go/maybe/no_go/insufficient_data), flags. FHA vs conventional rate by credit range. House hack rent adjustment. |
| `agents/listing_agent.py` | Orchestrator: geocode → scrape → underwrite → rank by verdict+CoC → return. Caches scrape results independently of profile. |
| `routes/listings.py` | `POST /listings/search` — accepts location + radius + optional user_profile |
| `routes/health.py` | `GET /health` — live ping of Zillow API + geocoder, returns green/yellow/red per service |
| `tests/test_underwriting.py` | 20 unit tests: mortgage math, expense components, verdicts, flags, house hack, FHA |
| `tests/test_zillow_scraper.py` | 11 unit tests + 1 skipped integration test: Haversine, address parser, normalizer |

**Key decisions:**
- `ZILLOW_MOCK_MODE=true` default in `.env` — full pipeline testable without any API key
- Geocode cached 24h (zip codes don't change), listings cached 1h
- Scraper is behind an interface — swap data source by editing one file
- All underwriting assumptions surfaced in response — nothing hidden
- Ranking: go → maybe → no_go by CoC descending when profile provided, else by distance

**Tests:** 31 pass, 1 skipped (integration, requires `ZILLOW_RUN_INTEGRATION=true`)

**Noted for later:** Add a database (likely SQLite → Postgres) to persist scraped listings so repeat searches return cached DB results + new listings only. The in-memory TTL cache handles this well enough for now.

## Observability, Health, & E2E Tests

**What was built:**

| File | Purpose |
|------|---------|
| `services/logger.py` | Structured JSON logger. Every log line is a JSON object. Error tag registry: `UH-GEO-xxx`, `UH-ZIL-xxx`, `UH-UW-xxx`, `UH-REQ-xxx`, `UH-CFG-xxx` |
| `middleware/request_tracker.py` | FastAPI middleware: UUID request ID per request, latency tracking, slow request warnings (>3s), `X-Request-ID` + `X-Latency-MS` response headers |
| `routes/health.py` | Three endpoints: `GET /health` (liveness), `GET /health/report` (full readiness), `POST /health/ping` (cron-friendly, accepts source/env/note metadata) |
| `tests/e2e/conftest.py` | TestClient fixture, forces mock mode, clears cache between runs |
| `tests/e2e/test_mock_api.py` | 25 E2E tests covering full request chain with mock data — always runnable, no API key needed |
| `tests/e2e/test_live_api.py` | 6 E2E tests against real Zillow API — gated behind `ZILLOW_RUN_INTEGRATION=true` |

**Key decisions:**
- Error tags are `UH-{SERVICE}-{CODE}` format — traceable in any log aggregator
- Health ping (`POST /health/ping`) is cron-ready: accepts `{"source":"cron","env":"production"}` and logs it with the health status
- Request ID generated as UUID if not provided in `X-Request-ID` header — propagated downstream
- Test suite: 53 pass, 7 skipped (live). Run live: `ZILLOW_RUN_INTEGRATION=true pytest tests/e2e/test_live_api.py`

See AUTHENTICATION_PLAN.md (to be created). Stack: SQLAlchemy async + SQLite→Postgres, JWT (python-jose + passlib), user roles (user/admin), underwriting history table, admin routes behind role guard.
